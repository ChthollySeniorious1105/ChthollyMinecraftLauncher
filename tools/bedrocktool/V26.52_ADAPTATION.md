# BedrockTools v26.52 适配记录

本目录是独立维护的 BedrockTools 工作区。此次升级以工作区现有的 v26.45 清洁副本为输入，不从外部仓库同步代码；协议字段依据 Mojang 官方 Bedrock 协议变更记录，协议参考包保存在 `work/official-module-reference`。

## 目标

- Minecraft Bedrock Edition：26.52
- 协议版本：2193
- 协议代码版本：`1.26.52`
- 内容方块版本：`1.21.60.33`（`18168865`）
- 行为包 `format_version`：`1.26.50`
- Windows amd64 输出：`outputs/bundle-26.52/bedrocktool-v26.52-windows-amd64.exe`
- GUI 输出：`outputs/bundle-26.52/bedrocktool-v26.52-gui-windows-amd64.exe`

26.52 是 26.50/26.51 协议布局上的热修复，协议号仍为 2193。工作区输入文件中的协议常量实际为 `1.26.44`/`2168`，因此升级过程先保留了 `work/baseline-26.45-as-provided`，再把协议层切到 2193。

## 代码适配

- 将本地 Gophertunnel 协议文件更新到 2193 布局，保留 BedrockTools 自己的连接、认证和代理代码。
- 补齐 26.50 的 `MoveActorDelta`、`PlayerAuthInput`、炉子选项、录制开始、声音播放、BossEvent、记分板和物品事务字段布局。
- 更新 26.50 方块状态数据、物品标签和连接属性；窗格、铁栏杆、铜栏杆、栅栏、绊线以及楼梯现在能映射到新注册表的状态。
- 更新维度高度图、世界高度范围、区块内容版本和行为包格式版本。
- 26.52 热修复不再额外伪造协议字段；运行时版本字符串使用 `1.26.52`。

## 构建和验证

在工作区根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build_bedrocktool_bundle.ps1 -Mode windows -BuildGui
```

构建脚本使用本地 Go、模块缓存和离线测试；构建前会清理 `outputs` 下旧的 26.44、26.45、26.50 CLI/GUI 可执行文件。输出目录会生成 `BUNDLE_MANIFEST.json`，便于核对文件哈希。

已验证的检查：

```powershell
go test ./gophertunnel/minecraft/protocol/...
go test ./dragonfly/...
go test ./dragonfly/server/block
go test ./cmd/bedrocktool ./handlers/...
```

`utils/TestInvalidJsonFix` 仍受输入 HuJSON 的前导零用例影响，这是输入树已有的独立失败，与 26.52 协议适配无关。

## JSON-RPC 信令运行时修复

构建标记：`v26.52-adapted-signaling1`。Minecraft 版本仍为 `1.26.52`。

旧解析器会把无法识别的 JSON 对象按 `CONNECTREQUEST <数字> <SDP>` 拆分。
用 `{"Code":1,"Message":"Unable to deliver message to the target"}` 构造的服务错误
可以复现日志中的 `parse ConnectionID: ... parsing "to"`。错误被记录后，连接仍会
继续等待握手响应。用户提供的日志没有原始消息，因此本次还不能确定实际服务错误码。

现在会区分投递失败服务信封、投递回执和 WebRTC 信号。投递失败会结束本次信令等待，
保留错误码和原文；`Signaling_DeliveryNotification_V1_0` 回执不会再进入信号解析器。
未知 JSON 消息仍会报告格式错误，不会被默默忽略或拆成数字。区域信令主机解析不到时
仍尝试全局 `signal.franchise.minecraft-services.net`。

本地 WebSocket 测试覆盖服务确认请求之前/之后的投递失败、回执后继续接收大于 32 KiB
的握手响应，以及旧文本格式兼容性。以下检查通过，真实 Realm 连接需要用户重试确认：

```powershell
go test -count=1 ./utils/franchise/signaling ./utils/proxy ./utils/connectinfo
```
